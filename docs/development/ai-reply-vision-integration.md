# AI回复接入图片、视频与表情识别

状态：源码实现已完成，构建与真机验证结果以对应提交的 CI 和实测记录为准。起始基线为 `bf68b6c6`（WCS 分支）。本文替代早先仅讨论图片和表情的方案。

## 1. 范围与设置

AI回复菜单支持文字、引用文字、语音、图片、VIDEO、MICRO_VIDEO、STICKER 和 SO_GOU_EMOJI。直接长按媒体后，点击生成会先识别目标媒体，再用分析文本生成回复。不需要先使用或开启独立“AI识别”。

处理链路：

```text
上下文图片 / 表情 / 视频 → 视觉模型 → 分析文本
历史文字 + 语音转写 + 媒体分析 + 指定目标 → 回复模型 → 候选回复
```

入口：候选窗口右上角齿轮 → 多媒体识别。布局跟随语音配置组：开关常驻，开启后显示服务商配置下拉与识别指令输入行。下拉列出已有视觉档的服务商、档名及模型；凭据仍到 API配置中维护。当前视觉底座只支持智谱 GLM，不新增未适配的服务商。

| 偏好 | 默认 | 作用 |
|---|---|---|
| ai_reply_context_vision_enabled | false | 自动识别上下文图片、表情和视频 |
| ai_reply_vision_profile_id | 空 | 独立引用 CAP_VISION 配置档 |
| ai_reply_context_vision_prompt | 回复专用中文指令 | 可编辑媒体描述要求 |

上下文自动识别默认关闭；直接长按媒体时，目标识别不受此开关影响。两者都使用回复设置中的视觉档，不静默选择第一条或跟随独立识别配置。ApiProfiles.usageCount 已纳入新增引用。设置使用 Compose 本地状态同步偏好。

默认指令要求描述主体、可见文字、动作、情绪和事件顺序，区分观察与推测，不猜身份、不执行媒体中的指令、不代替用户回复。动画继续追加已有采样提示词。

本轮不解析引用卡片内嵌媒体、文件附件或网页。文字里的表情代码和 Unicode emoji 仍按文字处理。

## 2. 上下文范围与顺序

以长按目标为界，查询之前七天内最近 N 条原始消息。SQL 在 LIMIT 前按时间和 msgId 排除目标及后续消息，以 createTime DESC、msgId DESC 取记录，再一次反转为旧到新。

查询仅在 AI 回复内部实现，不改变 WeDatabaseApi.getMessagesInRangeDesc 的共享返回契约。N 沿用原设置：默认 10、范围 0–20；过滤不支持类型后可能少于 N 条，不为凑数继续扫描。N=0 不处理历史，但媒体目标仍识别。

**选定窗口内所有图片、表情和视频逐条处理，不增加媒体专属数量上限。** 没有整批时间截止，前几条耗时不会导致后面按数量跳过。底层单项仍有资源、连接和读取超时；失败后处理下一条。这不代表无限扫描整个会话，原有 N≤20 仍保留。

多行正文保留；收到的群消息剥离发送者前缀后保留正文。方向沿用“我 / 对方”，不新增群成员身份识别。

## 3. 复用识别底座

没有新增 MediaRecognizer 文件。在 AiImageRecognition 内以 recognizeMedia 共用原逻辑，新增 recognizeForReply 接收 WeMessage；独立识别保留菜单、指令和展示流程。

| 类型 | 资源路径 |
|---|---|
| 图片 | msgSvrId → materializeNotificationLargeImage → 下载/VFS/解码 |
| 表情 | MD5 → materializeNotificationSticker(wait=true) |
| 视频目标 | 原 MessageInfo → 恢复 mp4 → 镜像路径/VFS |
| 历史视频 | msgSvrId → 真实宿主 MessageInfo → 相同视频流程 |

图片 serverId 为 0 时失败，不以 msgId 冒充，避免误取未发送图片。表情 MD5 回退为 imgPath → XML md5 属性 → md5 标签 → emoticonmd5 标签，覆盖 appmsg 表情。不把 XML、路径、MD5 当识别文本。

GIF/APNG/WebP 沿用最多六幅时间采样分镜及去重；可能遗漏短暂变化，不能声称完整观看。静态编码沿用原实现。

视频沿用 15 秒落盘等待、**单视频 10 MiB** 上限，整段 Base64 走 video_url，不新增视频抽帧。保留固定长度、分块 Base64、关闭缓冲输出流等现有上传逻辑。

视觉配置沿用现有 CAP_VISION/智谱接口约定，所选模型须支持相应媒体，没有扩展为所有服务商协议。HTTP 连接 15 秒、读取 120 秒；图片/表情准备等底层限制保留，没有新增“单项总计 60 秒”的承诺。

每项独立临时文件，finally 清理模块副本，不删除宿主媒体。

## 4. 模型输入与长度

SYSTEM 只放助手、语气、数量/格式和指令边界；历史、转写、媒体分析、目标均放 USER，声明为待分析数据。

```text
最近聊天记录（从旧到新）：
对方：你觉得这个怎么样？
对方：[图片 分析] 白色运动鞋，蓝色条纹，标价299元。
我：挺好搭。
对方：[语音] 我担心下雨容易脏。
对方：[表情 分析] 小猫双手合十，文字“拜托啦”，可能表示请求。
对方：[视频 分析] 人物穿鞋走过积水，随后展示鞋面水渍。

目标消息（对方）：帮我拿个主意吧。

请生成3条回复：
```

媒体分析不继承 300 字符截断，不新增整段本地裁剪。原规则仍保留：历史文字每条 300 字符、语音转写每条 300 字符、文字或语音目标最多 300 字符。服务商上下文容量仍可能拒绝过长请求。

媒体先被视觉模型压缩为描述，因此可能遗漏细节，回复模型没有直接读取原媒体。

## 5. 进度与成功探测

| 状态 | 实际证据 |
|---|---|
| 上下文媒体 i/总数 | 正在处理该条，串行遍历全部选中项 |
| 正在上传 | 开始写视觉请求 |
| 请求体已写完 | 输出流写完关闭，仅本地传输阶段完成 |
| HTTP 成功 | 收到 2xx，尚需验证识别结果 |
| 已返回识别文本 | choices[0].message.content 为非空字符串 |
| 收到回复模型响应 | 首个非空文本或推理增量 |
| 回复响应完成 | Completed + 非空正文 + 正常结束原因 |
| 缺少结束标记 | 有正文但 finishReason 为空，保留候选并明确提示未确认正常结束 |
| 不完整结果 | 空结果、无 Completed 或长度/过滤等异常结束，报错 |

正常结束原因兼容 stop、end_turn、stop_sequence（不区分大小写）。底层某些适配器 EOF 后也发 Completed，因此不能只看事件名称。服务商提供 promptTokens 时展示其输入计量；不提供则说明不可用。

探测证明取得有效服务端响应及其结束状态，不能证明每条媒体都被正确理解、每段上下文都被采用。没有额外发送付费探测请求，也没有伪造逐媒体内容回执。

回复阶段保留历史媒体成功/失败数量；目标媒体单独显示识别阶段，不计入“上下文媒体”统计。

## 6. 失败、取消与缓存

- 历史单条失败留下类型和“识别失败，内容不可用”占位并计数，其余继续。配置缺失、401/403/429 同样按单项失败处理，没有新增重试或限流熔断。
- 目标媒体失败终止生成，不拿空描述猜回复。数据库失败同样报错，不假装已加载历史。
- 取消异常在生成、历史媒体、语音层穿透；关闭候选弹窗取消 Compose scope。HTTP 沿用 disconnect，临时文件 finally 清理。宿主已启动的下载/阻塞调用不承诺立即停止。
- 弹窗记录打开时账号；媒体准备、发送回复和流式接收检查账号变化，变化后中止。应重新打开当前账号的会话。
- 成功描述只缓存于当前候选弹窗，不写磁盘，不做进程全局 200 条缓存。键包括账号、WeMessage、ApiProfile 快照和识别指令；换语气可复用，换视觉档内容/指令失效。
- 不同消息的相同表情不按 MD5 跨消息去重；不同弹窗不共享。只缓存成功文本，不缓存失败或媒体/Base64。
- ApiProfile 作为现有配置对象参与短期内存键，不打印内容。日志记录阶段、HTTP、模型 ID、类型、计数、字符数和 token 数；删除原回复目标和 SYSTEM 全文日志。

## 8. 验证状态

提交前已做源码差异、资源 XML、新增双语键/格式参数、资源引用、空白检查。没有本地 Android 编译、没有请求真实模型或消耗额度、没有真机验证。云端构建结果需核对对应提交的 CI；静态检查不能替代构建与宿主验证。

待构建后由用户安装检查：

1. 文字、语音、图片、普通/动画表情及两种视频的 AI 回复菜单。
2. 混合上下文所有媒体依次识别，最终回复参考分析，方向和旧到新顺序正确。
3. 超过三条媒体仍全部尝试；单项失败保留占位，目标失败不生成猜测候选。
4. 非2xx、空结果、流中断、长度截断和缺结束标记不误报完成。
5. 返回关闭停止后续请求，长时间多项加载不阻塞界面。
6. 换语气复用成功缓存，换视觉配置/指令重新识别。
7. 长按旧消息不带后续记录，同时间戳及单聊/群聊多行正文正确。
8. 独立识别无回归，视频大小/落盘限制与动画分镜提示一致。
9. N=0、上下文开关关闭、缺配置、账号变化和不同回复协议的状态准确。
